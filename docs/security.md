# Security

> How Money4Band protects your credentials and containers.

---

## Credential Encryption

All sensitive data in `user-config.json` is encrypted at rest using **Fernet** (AES-128-CBC + HMAC-SHA256, via the `cryptography` library).

### How It Works

1. **Master key** is stored at `~/.m4b/master.key` with restricted file permissions (`0o600`).
2. On first run, if no key exists, one is generated automatically.
3. When M4B exits (via `atexit` or `SIGTERM`), credentials are encrypted before writing to disk.
4. On startup, credentials are decrypted in memory for use.
5. Encrypted values are prefixed with `M4B_ENCRYPTED:` for detection.

### Key Management

- The master key **never** leaves your machine.
- It is **never** included in backups or Docker volumes.
- File permissions are set to owner-only read/write.
- If you lose the key, you must re-enter your credentials via `m4b setup`.

## Log Scrubbing

A `CredentialScrubFilter` is installed on all loggers. It uses regex patterns to detect and redact:

- Email addresses
- API tokens and keys
- Passwords
- Any value matching known credential field patterns

Scrubbing is applied to both file and console log output.

## Docker Container Hardening

Every container generated by M4B includes security options:

| Measure | Description |
|---------|-------------|
| `security_opt: [no-new-privileges:true]` | Prevents privilege escalation inside containers |
| `read_only: true` | Applied to Watchtower — filesystem is read-only |
| Watchtower scope labels | Prevents cross-project container interference |
| Centralised DNS | All containers use configured DNS servers |
| Network isolation | Dedicated bridge network with defined subnet |

## Docker Image Security

Run security checks on your configured app images:

```bash
m4b validate
```

This checks:
- Image tag pinning (avoid `:latest` where possible)
- Known vulnerability databases
- Image source verification

## Backup Security

- Backups at `~/.m4b/backups/` preserve encryption state.
- If your config is encrypted when backed up, the backup file is also encrypted.
- Restoration requires the same master key that was used to encrypt.

## Best Practices

1. **Don't share** `~/.m4b/master.key` or `config/user-config.json`.
2. **Use `m4b backup`** regularly to protect against data loss.
3. **Keep M4B updated** (`m4b update`) for security patches.
4. **Review IP quality** (`m4b ip`) — some proxy providers may flag your IP.
5. **Use the dashboard locally** — avoid exposing it to the internet without HTTPS.
6. **Dashboard cookie auth** — when using web-exposed mode, the API key is stored as an `httpOnly`, `samesite=strict` cookie.
